# TickHub

Android app that turns your phone into a reliable GitHub Actions scheduler.

把手机变成 GitHub Actions 的调度中心：登录 GitHub → 扫描仓库与工作流 → 配置触发规则（时间 + 周期）→ 手机按时 `POST /dispatches` 触发工作流，替代 unreliable 的 `on.schedule`。

## 构建

构建完全走 GitHub Actions，本地无需 Android SDK：

- 打 tag `v0.1.0-beta1` 并 push → Actions 自动构建签名 APK 并发布为 prerelease。
- 或在 Actions 页手动触发 `workflow_dispatch` → 产出未发布的 APK artifact。

签名密钥存于仓库 Secrets，有效期至 2054 年，后续更新可直接覆盖安装。

## 权限说明

APP 需要以下权限才能可靠定时：

- 自启动（国产 ROM 必须手动开启）
- 电池无限制 / 忽略电池优化
- 通知权限（Android 13+）

APP 只在触发时发一个 HTTPS 请求，业务结果由各仓库原有的 WxPusher 推送。

## 使用说明

1. **安装**：从 Releases 下载最新 beta APK，直接覆盖安装即可（同一签名）。
2. **登录**：打开 APP → 点「使用 GitHub 登录」→ 浏览器出现设备码，输入并授权 → **切回 APP**（切后台期间可能提示"网络不可达，正在重试"，几秒后自动成功，属正常现象）。
3. **配置权限**：进「设置」页，开启「电池无限制」、「自启动设置」（跳应用详情页找自启动开关）、「精确闹钟」。这三步是国产 ROM 后台定时可靠性的关键，缺一可能延迟或漏触发。
4. **扫描仓库**：回「仓库」页 → 点「扫描仓库与工作流」→ 展开目标仓库 → 勾选要纳管的工作流。点工作流右侧「立即触发」可验证链路是否通。
5. **创建规则**：进「规则」页 → 新建 → ①先点仓库展开、勾选该仓库的工作流（可跨仓库多选，保存时会自动拆成各自仓库的独立规则）→ ②设触发时间（点「修改」弹拨轮，"＋添加时间段"可设一天多次触发）→ ③选周期（单次/每天/每周/法定工作日/法定节假日/每隔X天）→ ④可选随机漂移（10/30/60 分钟）→ 保存。卡片显示下次触发时间和漂移窗口。
   - 执行状态：触发中的规则卡片会显示转圈和已用时长，完成后才写入历史（历史也显示耗时）。这是纯前台显示，不额外耗电，可在设置页关闭。
6. **验证**：先用「立即触发」确认"历史"页出现成功记录；再建一条几分钟后的规则验证自动触发。
7. **排障**：到点没触发时，进「设置」页底部「调试日志」入口，点「复制全部」导出调试日志（记录闹钟注册/触发、网络等待、dispatch 每次尝试的 HTTP 码与错误），发给开发者分析。日志不含 token 或设备码。

### 卡片操作（三个页面通用）

- **左滑**卡片到一定程度松手 → 右侧红色删除图标常驻（不会自动删），点图标确认删除，点卡片取消。
- **长按**卡片任意位置 → 进入多选模式，顶部出现「全选 / 删除 / 取消」，整卡高亮。
